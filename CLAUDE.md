# logic_error_searcher — «Ловец логических ошибок»

Статический веб-тренажёр: короткая сценка → выбрать тип логической ошибки (или
«ошибки нет») → разбор. Все сценки оригинальные. Схема данных, правила разметки
и скрипты подробно описаны в `README.md` — не дублировать, а обновлять его.

## Что где

- `index.html`, `css/style.css`, `js/app.js` — приложение без сборщиков и
  фреймворков; прогресс в `localStorage` (ключ `lfs.v1` — при несовместимой смене
  формата менять версию ключа).
- `data/fallacies.json` — справочник типов, семейств и пересечений; поле `counter` —
  советы для вкладки «Как спорить» (общие принципы — статичным текстом в `index.html`).
- `data/easter.json` — пасхальные вопросы (сейчас один, после 100 верных ответов).
  Исключение из всех правил разметки, валидатор их не проверяет.
- `data/questions.json` — вопросы (на 2026-10: 267 шт., пачки 1–6).
- `data/bundle.js` — **генерируется** `validate.js --write`, руками не править;
  нужен, чтобы `index.html` работал по двойному клику (file://).
- `scripts/validate.js`, `scripts/plan-batch.js` — Node без зависимостей.

## Правила

- Ответ — самый точный ярлык; общая категория (`parent`) засчитывается частично.
  Допустимые, но менее точные варианты — в `also_accepted`, адресные пояснения к
  неверным выборам — в `pick_notes`.
- Отвлекающие варианты — правдоподобные, из того же/соседнего семейства или из
  `overlaps`; не добавлять вариант «для количества», если его никто не выберет.
- Новые сценки не должны перефразировать старые (валидатор проверяет пересечение
  основ слов) и должны быть однозначными: ошибка видна в `highlight`, а реплики
  других персонажей не уводят в сторону.
- Поля `disputed` / `dispute_reasons` ставит валидатор; ручное решение по спорным —
  через `review`.
- Новая пачка: `node scripts/plan-batch.js` → 50 вопросов → `node scripts/validate.js
  --write` → исправить ошибки, показать Дмитрию спорные.
- Интерфейс проверять в браузере и по file://, и через `npm run serve`.
