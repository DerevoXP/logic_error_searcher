# Ловец логических ошибок

Статический веб-тренажёр: читаете короткую сценку, выбираете, какая логическая ошибка в ней допущена, получаете разбор. Все примеры оригинальные.

## Запуск

- Двойной клик по `index.html` — работает через `data/bundle.js` (собирается валидатором).
- Или локальный сервер: `python -m http.server 8000` → http://localhost:8000 — тогда данные читаются прямо из JSON.

Прогресс, режим и фильтры хранятся в `localStorage` браузера (ключ `lfs.v1`).

## Данные

- `data/fallacies.json` — справочник: `families` (семейства и их соседи), для каждого типа `id`, `name`, `latin`, `aliases`, `family`, `parent` (общая категория, если тип — её частный случай), `definition`, `cues` (регулярки-маркеры для проверки неоднозначности), `counter` — совет для вкладки «Как спорить» и для свёрнутого блока под разбором: `{how, say: [фразы], avoid?}`; `overlaps` — пары типов, которые легко спутать. Общие принципы «Как спорить» — статичный текст прямо в `index.html`.
- `data/easter.json` — пасхальные вопросы. Валидатор их **не проверяет**, только кладёт в `bundle.js`. Свои варианты ответа текстом: `options: [{text, correct?, note?, last?}]` (`last` — всегда в конце списка), `prompt` — вопрос над вариантами, `explanation` — разбор (абзацы через пустую строку), `unlock_correct` — после скольких верных ответов за всё время показать (частичный зачёт не считается). Показывается один раз; в счёт сессии и статистику не идёт; ответ хранится в `localStorage` в `eggs`, «Сбросить прогресс» его тоже стирает.

**Правило разметки: ответ — самый точный ярлык.** Общая категория ответа (`parent`, например «подмена тезиса» для «соломенного чучела» или «мнимое следование» для «утверждения следствия») засчитывается частично автоматически. Если среди вариантов есть частный случай ответа, валидатор требует объяснить, почему он не подходит.
- `data/questions.json` — вопросы:

| поле | смысл |
|---|---|
| `id`, `batch` | `q001…`, номер пачки по 50 |
| `text` | сценка, 2–6 предложений |
| `answer_id` | правильный тип или `none` («ошибки нет») |
| `distractors` | пул из 3–6 отвлекающих id (без `none`); при показе берётся `nearest_distractor` + случайные до трёх |
| `offer_none` | показывать ли вариант «ошибки нет» |
| `highlight` | дословная цитата из `text`, где ошибка |
| `explanation` | почему это именно эта ошибка |
| `nearest_distractor`, `contrast` | ближайший отвлекающий вариант и чем от него отличается |
| `also_accepted` | `[{id, note}]` — допустимые, но менее точные ярлыки: частичный зачёт (полбалла, в «ошибки» не попадает) |
| `pick_notes` | `{id: текст}` — адресное пояснение, если выбран этот неверный вариант |
| `difficulty` | 1–3 |
| `review` | ручное ревью: `{status: "ok" \| "disputed", note}` |
| `disputed`, `dispute_reasons` | выставляются валидатором, руками не править |

## Скрипты

```
node scripts/validate.js            # отчёт: структура, дубли, баланс, неоднозначность
node scripts/validate.js --verbose  # плюс мелкие заметки
node scripts/validate.js --write    # записать флаги спорности и пересобрать data/bundle.js
node scripts/plan-batch.js          # квоты и диапазон id для следующей пачки
```

Проход неоднозначности помечает вопрос спорным, если маркеры отвлекающего типа в тексте не слабее маркеров ответа, если пара «ответ — отвлекающий» попадает в известное пересечение и маркеры партнёра есть в тексте, если в вопросе «ошибки нет» сильно звучат маркеры какой-то ошибки или если ревьюер поставил `review.status = "disputed"`. `review.status = "ok"` снимает эвристический флаг. Варианты из `also_accepted` считаются уже разрешённой двусмысленностью и не проверяются.

Дополнительно валидатор предупреждает:
- об отвлекающих, которые никто не выберет (не из того же или соседнего семейства, не из `overlaps` и не `nearest_distractor`);
- о возможном перефразировании: у двух сценок много общих основ слов (порог 0.2, при одинаковом ответе — 0.15).

## Добавление пачки

1. `node scripts/plan-batch.js` — получить квоты.
2. Дописать 50 вопросов в `data/questions.json` с новым `batch`.
3. `node scripts/validate.js --write` — исправить ошибки, просмотреть спорные.
